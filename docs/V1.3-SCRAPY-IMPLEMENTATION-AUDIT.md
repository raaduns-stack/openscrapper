# V1.3 Scrapy Implementation Audit

**Status:** Engineering audit against the approved Scrapy-native architecture.
**Authority:** V1.3 Source of Truth + approved Scrapy-native architecture addendum.

## Executive decision

The current collector is functional, but Scrapy is still wrapped by too much custom crawl orchestration.

The target is to make Scrapy the crawl engine and keep Claw-specific business logic outside it.

Current implementation is therefore classified as **REWRITE / MOVE**, not a small tuning exercise.

## Responsibility boundary

### KEEP in Claw

- SearchCriteria and query strategy.
- Manual/Premium SERP acquisition.
- Scrap ownership, billing, limits and lifecycle.
- URL occurrence persistence and provenance.
- Domain policy and client policy.
- Lead extraction and enrichment.
- Pydantic validation/self-correction.
- Lead qualification.
- Lead deduplication.
- PostgreSQL business persistence.
- CSV, Excel and Google Sheets exports.
- OpenClaw as an optional final browser adapter.

### MOVE into Scrapy

- Crawl scheduling and request queue.
- Seed request creation.
- Internal-link request generation.
- Crawl depth/bounds.
- Retry and download failure handling.
- Redirect handling.
- Robots handling.
- Per-domain concurrency and throttling.
- Response classification and crawl diagnostics.
- Conditional browser escalation.
- Crawl statistics and lifecycle signals.
- Crawl item production.
- Document response acquisition.

### DELETE from crawl orchestration

- Python-side crawl queue/state as an authoritative scheduler.
- Separate manual pagination crawling for ordinary HTML links.
- Global Playwright handling for every HTTP request.
- Custom stdout telemetry as the primary crawl telemetry mechanism.
- Duplicate/content fingerprinting that changes URL-occurrence semantics.
- Browser escalation loops outside the Scrapy request lifecycle.

## File-by-file map

### `src/collector/scrapy_runner.py`

**Decision: REWRITE — becomes the primary Scrapy engine.**

KEEP:
- `CollectedPage` compatibility boundary, temporarily.
- `CollectionSpider`.
- Scrapy `Request`/`Spider` model.
- `LinkExtractor` where useful.
- `CrawlPageItem` concept.
- Downloader diagnostics middleware.
- Scrapy signals/statistics integration.
- Robots, retries, AutoThrottle and concurrency settings.

REWRITE:
- Seed scheduling so every valid seed occurrence enters Scrapy up to URL budget.
- Internal-link expansion so Scrapy owns the complete request graph.
- URL occurrence accounting so no URL deduplication is introduced.
- Page limit semantics independently from URL-occurrence limit.
- Conditional Playwright escalation.
- Crawl failure classification.
- Telemetry emission from Scrapy stats/signals.
- Item pipeline boundary.

DELETE/REPLACE:
- Global Playwright download handler configuration.
- Manual `max_pages` truncation of initial seeds.
- Any Scrapy/application split that makes the Python controller another scheduler.

### `src/collector/collection_controller.py`

**Decision: MAJOR REWRITE.**

It currently implements a second crawl controller around Scrapy: batches, pending URLs, pagination, state and escalation.

Target role:
- Thin application adapter only.
- Construct crawl policy from V1.3 configuration.
- Invoke Scrapy crawl.
- Receive normalized crawl items/results.
- Never schedule URLs itself.
- Never own visited/queued state.
- Never implement ordinary HTML pagination.

The existing `_collect_batch()` and `collect()` orchestration should be removed after the new Scrapy engine is proven.

### `src/collector/crawl_state.py`

**Decision: DELETE after migration.**

Reason:
- `visited`, `queued`, `pages_collected` and exhaustion are duplicate crawler state.
- Scrapy Scheduler and crawler stats should own crawl execution state.
- URL occurrence limits must be enforced by the Scrapy crawl policy, not a second queue.

Client/business persistence remains in PostgreSQL; this file is not that persistence layer.

### `src/collector/pagination.py`

**Decision: DELETE from normal crawl path.**

Scrapy Spider link discovery should handle normal `<a>` navigation and bounded same-domain expansion.

Dynamic `Load More` / JS pagination is a browser-escalation concern and should be represented by conditional Playwright requests, not a separate crawler loop.

Any future pagination-specific policy belongs in the Scrapy crawl policy/middleware layer.

### `src/collector/browser_escalation.py`

**Decision: REWRITE / MOVE policy into Scrapy.**

The idea of bounded escalation is KEEP.

The current controller should not sit after an entire Scrapy crawl and re-run failed pages as a separate collection phase.

Target:
- Scrapy receives normal HTTP response first.
- Middleware/Spider determines whether browser rendering is required.
- A bounded Playwright request is scheduled through Scrapy.
- Result returns through the same Spider/item pipeline.
- Escalation count is captured by Scrapy stats.

### `src/collector/openclaw_escalation.py`

**Decision: KEEP as optional adapter; remove from primary crawl path.**

OpenClaw remains available for pages requiring real browser interaction after normal Scrapy + conditional Playwright handling.

It must remain bounded and must not become a second crawler.

### `src/collector/evidence.py`

**Decision: KEEP, but move evidence creation downstream.**

This is not crawler infrastructure. Scrapy should acquire the response/item; the existing evidence/extraction pipeline interprets it.

### `src/collector/worker.py`

**Decision: REWRITE.**

Current subprocess isolation may remain temporarily, but the worker must expose Scrapy's crawl lifecycle cleanly.

The long-term interface should be:
- application submits crawl job/policy;
- Scrapy runs the crawl;
- Scrapy stats/signals/items provide structured results;
- PostgreSQL receives persistent crawl outcomes;
- no custom `CLAW_PROGRESS` protocol is required as crawler truth.

If process isolation is retained, it is an execution boundary, not a second crawl abstraction.

## Important defects exposed by the audit

1. Current `_requests()` historically couples seed submission to `max_pages`; this can prevent all valid seeds from entering Scrapy.
2. Current internal requests rely on Scrapy duplicate filtering while V1.3 explicitly removes URL deduplication.
3. All HTTP/HTTPS requests are currently configured through Playwright, which defeats the intended normal-HTTP-first architecture.
4. `CollectionController` still owns crawl queues, visited state and pagination outside Scrapy.
5. Crawl telemetry is duplicated between Scrapy stats, custom callbacks and subprocess stdout.
6. Crawl-page persistence currently happens downstream rather than as a clean Scrapy item boundary.
7. Individual failed URL outcomes and worker-level failures need distinct semantics.

## Target crawl flow

```text
Valid SERP URL occurrences
        ↓
Claw CrawlPolicy
        ↓
Scrapy Spider
        ↓
Scrapy Scheduler
        ↓
Downloader Middleware
        ↓
Normal HTTP download
        ↓
Conditional Playwright escalation when required
        ↓
Spider response handling
        ↓
Bounded same-domain link expansion
        ↓
CrawlPageItem
        ↓
Scrapy Item Pipeline
        ↓
PostgreSQL crawl outcome / downstream evidence
        ↓
Existing extraction → validation → qualification → dedupe → export
```

## Implementation verification — 2026-09-15

The implementation has now been brought to the approved Scrapy-native boundary.

- `scrapy_runner.py` is the primary crawl engine and owns seed scheduling, request graph, depth/bounds, retries, robots, throttling, conditional Playwright escalation, stats/signals, and crawl items.
- Initial valid seed occurrences are not truncated by `max_crawl_pages`; URL-occurrence budget is independent.
- Scrapy duplicate filtering is bypassed for crawl requests so repeated SERP URL occurrences remain separate inputs.
- Crawl pages are persisted at the Scrapy Item Pipeline boundary, including failed occurrences and occurrence indexes.
- `run_harvested()` passes `scrap_id` into the Scrapy collector, preserving persistence for manual/premium harvested paths.
- Premium extraction accepts both the native paginated `search_all()` client and simple injected `search()` clients.
- `collection_controller.py` remains only as a compatibility/application adapter; it is not the crawl engine.
- Obsolete `crawl_state.py` and `pagination.py` are absent from the active collector architecture.
- Obsolete `browser_escalation.py` and `paginator.legacy.py` were removed; `openclaw_escalation.py` remains the optional adapter.
- Stale tests for the removed browser controller were removed with the obsolete implementation.
- Test-only Fernet configuration is generated in `tests/conftest.py`; production still requires `PREMIUM_PROVIDER_ENCRYPTION_KEY` to be explicitly configured.
- Local PostgreSQL authentication was repaired to match the repository development configuration; no application credential change was made.
- Targeted collector/persistence tests: **23 passed**.
- Full repository test suite after cleanup: **136 passed**.

This verification section supersedes earlier audit statements that described the Scrapy migration as still pending. The remaining work is final regression verification and review of any non-Scrapy legacy code outside the crawl path.
