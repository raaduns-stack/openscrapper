# V1.3 Addendum — Bounded Scrapy Crawl

**Status:** Approved implementation addendum to V1.3.

## Purpose

Scrapy is the primary collection engine for all valid URLs returned by Discovery.
Discovery candidates are seed URLs, not a ranked set of pages to discard.

## Requirements

- Every valid Discovery seed URL is submitted to Scrapy, subject to the configured URL budget.
- Scrapy crawls seed URLs and may follow relevant same-domain internal links.
- Internal-link expansion is navigation control only; there is no page priority or lead-quality scoring.
- Link expansion is limited to useful contact/research paths such as contact, team, staff, people, management, directory, procurement, purchasing, sales, and buyer paths.
- All collected pages and documents remain available to the downstream evidence/extraction pipeline.
- Seed URLs are never displaced by internal-link expansion.
- Existing URL validity, URL deduplication, crawl-page, crawl-URL, pagination, and exhaustion controls remain governing bounds.
- Scrapy continues to provide scheduling, concurrency, retries, redirects, robots handling, AutoThrottle, and Playwright integration.
- Collection remains responsible only for acquisition; extraction and lead qualification remain downstream.

## Architectural flow

Discovery → valid seed URLs → Scrapy seeds → bounded internal-link expansion → evidence/content → extraction.

No semantic URL scoring or priority queue is introduced by this addendum.
